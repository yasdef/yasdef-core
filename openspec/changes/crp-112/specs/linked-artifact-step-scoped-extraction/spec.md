## ADDED Requirements

### Requirement: Design phase MUST extract a step-scoped LAR shortlist as a third filter stage
`ai/scripts/ai_design.sh` SHALL perform a third filter stage after collecting `[REQ-X]` tags from step bullets and extracting matching `### Requirement N` blocks from `overmind/reqirements_ears.md`. The third stage SHALL scan only those extracted blocks for `**Linked Artifacts:**` lines, collect the unique `LAR-NNN` IDs, look each ID up in the bottom `## Linked Artifacts` registry of `overmind/reqirements_ears.md`, and emit a context block named `## Linked Artifacts (in scope)` containing one line per LAR formatted as `- LAR-NNN | <type> | <title> | <locator>` with deterministic ascending-numeric-ID ordering.

#### Scenario: Step bullets reference LAR-tagged requirements
- **WHEN** `ai/scripts/ai_design.sh` runs for a step whose bullets reference a REQ whose `### Requirement N` block in `overmind/reqirements_ears.md` contains a `**Linked Artifacts:** LAR-002` line
- **AND** the bottom `## Linked Artifacts` registry contains `id: LAR-002`, `title`, `type`, `locator`
- **THEN** the design prompt context contains a `## Linked Artifacts (in scope)` block with `- LAR-002 | <type> | <title> | <locator>`

#### Scenario: Step bullets reference no LAR-tagged requirements
- **WHEN** `ai/scripts/ai_design.sh` runs for a step whose extracted `### Requirement N` blocks contain no `**Linked Artifacts:**` lines
- **THEN** the design prompt context emits an empty `## Linked Artifacts (in scope)` block or omits the block entirely
- **THEN** the rest of the design prompt is unchanged

#### Scenario: Multiple LARs are deduplicated and ordered
- **WHEN** the extracted requirement blocks reference `LAR-005`, `LAR-001`, and `LAR-005` again across multiple `**Linked Artifacts:**` lines
- **THEN** the emitted block contains `LAR-001` first and `LAR-005` second
- **THEN** `LAR-005` appears exactly once

### Requirement: A dedicated helper MUST sync the in-scope LAR shortlist into the design artifact
A new helper `ai/scripts/helpers/sync_step_lars.sh <step> <target-artifact-path>` SHALL recompute the LAR funnel from `overmind/implementation_plan.md` and `overmind/reqirements_ears.md` and idempotently write/replace a `## Linked Artifacts (in scope)` section in the target artifact at the given path. The design prompt SHALL instruct the model to invoke the helper with `ai/step_designs/step-<N>-design.md` as the target path so the section lands deterministically rather than being echoed by the model.

#### Scenario: Helper writes the section into a design artifact that lacks it
- **WHEN** the helper runs for a step whose design artifact does not yet contain `## Linked Artifacts (in scope)` and whose extracted REQ blocks reference one or more LARs
- **THEN** the helper appends a `## Linked Artifacts (in scope)` section to the design artifact
- **THEN** the section contains one line per LAR formatted as `- LAR-NNN | <type> | <title> | <locator>` ordered by ascending numeric ID

#### Scenario: Helper replaces an existing section idempotently
- **WHEN** the helper runs for a step whose design artifact already contains a `## Linked Artifacts (in scope)` section
- **THEN** the existing section is replaced with the freshly recomputed section
- **THEN** running the helper again produces a byte-equivalent design artifact

#### Scenario: Helper handles a step with no LARs as a no-op
- **WHEN** the helper runs for a step whose extracted REQ blocks contain no `**Linked Artifacts:**` references
- **THEN** the design artifact is left in a state with either no `## Linked Artifacts (in scope)` section or an empty one
- **THEN** the helper exits successfully

#### Scenario: Design phase invokes the helper instead of echoing the section
- **WHEN** the design prompt is generated by `ai/scripts/ai_design.sh`
- **THEN** the prompt instructs the model to invoke `ai/scripts/helpers/sync_step_lars.sh <step> ai/step_designs/step-<N>-design.md` for artifact-side syncing of the section
- **THEN** the prompt does not require the model to echo the `## Linked Artifacts (in scope)` block textually into the design artifact

### Requirement: Mid and downstream phases SHALL consume the in-scope LAR shortlist from the upstream artifact
Planning SHALL consume the shortlist from the design artifact and implementation SHALL consume it from the step plan, so the design-phase funnel result is the single source of truth.

#### Scenario: Planning consumes the shortlist from the design artifact
- **WHEN** `ai/scripts/ai_plan.sh` builds the planning prompt context for a step
- **THEN** any `## Linked Artifacts (in scope)` content is sourced from `ai/step_designs/step-<N>-design.md`

#### Scenario: Implementation consumes the shortlist from the step plan
- **WHEN** `ai/scripts/ai_implementation.sh` builds the implementation prompt context for a step
- **THEN** any `## Linked Artifacts (in scope)` content is sourced from `ai/step_plans/step-<N>.md`
