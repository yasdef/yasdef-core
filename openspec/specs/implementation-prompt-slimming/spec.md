## ADDED Requirements

### Requirement: Implementation prompt MUST invoke the implementation skill compactly
The implementation prompt generated by `ai/scripts/orchestrator.sh` MUST name `yasdef-worker-implementation` and pass only explicit phase variables.

#### Scenario: Compact contract is present
- **WHEN** implementation prompt content is generated for a step
- **THEN** it includes the selected step, feature id, branch, step plan path, design artifact path, and runtime implementation plan path

#### Scenario: Contract remains phase-scoped
- **WHEN** implementation prompt content is generated
- **THEN** it avoids re-emitting implementation workflow rules that belong to the implementation skill

### Requirement: Implementation skill MUST reference authoritative process rules
Implementation skill output and instructions MUST reference the installed skill and process rules as the authoritative source for detailed implementation-phase workflow and gates.

#### Scenario: Authoritative source is explicit
- **WHEN** implementation prompt content is generated
- **THEN** it explicitly points to `yasdef-worker-implementation`

#### Scenario: Rule de-duplication is preserved
- **WHEN** implementation prompt strings are updated
- **THEN** detailed process text remains centralized in `ai/AI_DEVELOPMENT_PROCESS.md` and `.codex/skills/yasdef-worker-implementation/SKILL.md` rather than duplicated in orchestrator prompt output

### Requirement: Context builder MUST keep step-specific implementation inputs
The implementation skill context builder MUST retain step-specific execution inputs required for correct implementation work, including ordered plan bullets, constraints, tests/risks, translated FRs, linked artifacts, and the design scope contract.

#### Scenario: Required step context remains available
- **WHEN** implementation context content is generated after slimming
- **THEN** it still includes ordered bullets, key constraints, tests/risks, and linked requirements excerpts needed for execution

#### Scenario: Redundant summaries are removed
- **WHEN** implementation context content is generated
- **THEN** redundant process-summary content that duplicates global process rules is omitted from the context pack

### Requirement: Prompt-focused tests MUST guard compactness and behavior
Test suites MUST verify compact prompt presence, skill context behavior, and absence of removed duplicated design/process text.

#### Scenario: Compact contract assertions pass
- **WHEN** prompt-focused script tests run
- **THEN** tests assert the implementation prompt names `yasdef-worker-implementation` and passes variables only

#### Scenario: Size regression is detected
- **WHEN** implementation context output includes forbidden duplicated design/process sections
- **THEN** skill helper tests fail with clear guidance that de-duplication regressed
